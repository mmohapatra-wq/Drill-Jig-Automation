2. What a “hybrid .cmd” is

One file, two languages
Each tool is a SINGLE file that is BOTH a Windows batch script AND a PowerShell script. The batch header at the top relaunches powershell.exe -STA and executes the embedded body via [scriptblock]::Create(...). One double-click — no install, no external .ps1 needed.

The header on line 4 re-anchors $ScriptDir to the repo root, so lib\, data\, docs\ and the cross-tool handoff JSONs resolve identically no matter which subfolder the tool lives in. The -STA apartment state is what lets the embedded WinForms wizards work. The net effect: portable, self-contained tools that you run by double-clicking.

4. Register the Creo VB API COM objects

What this does / why: the tools connect to Creo through COM objects (ProgIDs like pfcls.pfcAsyncConnection). Those objects have to be registered with Windows once per machine. Run this as Administrator.

cd "C:\PTC\Creo 12.4.3.0\Parametric\bin"
.\vb_api_register.bat
Self-healing
Every tool retries registration automatically on first run if New-Object -ComObject pfcls.pfcAsyncConnection throws — so a fresh machine often just works on the second attempt.

How the connection works

Get-Process xtop                       # find the running Creo process
  -> set $Env:PRO_DIRECTORY and $Env:PRO_COMM_MSG_EXE from its path
$async      = New-Object -ComObject pfcls.pfcAsyncConnection
$connection = $async.Connect($null,$null,$null,$null)
$session    = $connection.Session
$model      = $session.GetActiveModel()
Environment expectations
Tools expect exactly ONE xtop.exe running and the jig PART open — not an .asm assembly.

What the semantic search actually does
The VB API HTML docs are parsed into chunks; each chunk is embedded into a 384-dim vector by all-MiniLM-L6-v2 and stored in a FAISS cosine index. Your query is embedded the same way and the nearest chunks are returned (<0.1 ms/query). function mode instead does a direct name→doc lookup.

6. Register vb-docs in Claude Code (stdio)

What this does / why: this tells Claude Code how to launch the local server so its one tool becomes available in your sessions.

Use the direct venv python path
Point at the .venv python directly — NOT uv run. It is more reliable: no dependency resolution at launch, no working-directory dependency.

Add to ~/.claude.json:

"mcpServers": {
  "vb-docs": {
    "type": "stdio",
    "command": "C:\\Users\\mmohapatra\\creo_vb_api_docs_mcp\\.venv\\Scripts\\python.exe",
    "args": ["C:\\Users\\mmohapatra\\creo_vb_api_docs_mcp\\src\\vb_docs\\mcp_server.py"]
  }
}

Or register via CLI:

claude mcp add vb-docs --scope user -- "C:\Users\YOUR_USERNAME\creo_vb_api_docs_mcp\.venv\Scripts\python.exe" "C:\Users\YOUR_USERNAME\creo_vb_api_docs_mcp\src\vb_docs\mcp_server.py"

Restart Claude Code. It exposes ONE tool: query_vb_api_docs (query required; mode = auto|function|semantic, default auto; limit 1–20, default 5).

7. What MCP is

Model Context Protocol, in one line
MCP is a standard by which a “server” exposes tools/resources to Claude Code. vb-docs is a LOCAL stdio server (a Python process on your machine); the Leap fleet below are HOSTED http servers.

9. Efficient querying — the whole point of vb-docs

Rule from CLAUDE.md: when writing or debugging VB API code, verify method signatures, parameters, and return types via vb-docs BEFORE relying on memory.

Query modes

  • mode=function — exact name lookup, O(1). Use for IpfcSession, RunMacro, CMpfcSelect, EpfcModelType.
  • mode=semantic — natural language. Use for “how to create a feature”.
  • mode=auto — default; picks for you.

Keep it cheap

  • Query narrow — one symbol or concept.
  • Take the top hit; use a small limit.
  • For a CMpfc* / CCpfc* class factory, confirm the real ProgID — those are never standalone ProgIDs.

The confirmed-facts registry lib\creo_api_facts.json (query via lib\creo_api_facts.ps1) records live-verified and refuted API facts — e.g. “plane normals read null on this build”, “IpfcPoint.Point crashes”, “use the pfcls.pfcRegenInstructions ProgID, not CC*”. Auto-approve the tool so lookups never prompt — in the repo’s .claude\settings.local.json: permissions.allow = ["mcp__vb-docs__query_vb_api_docs"]. The vb-docs repo also ships slash commands / a skill: /creo-pwsh-vb-session, /creo-pwsh-vb-debug, and the creo-vb-api skill.

10. The F8 interactive loop

What this does / why: instead of guessing, you run tiny snippets against the live Creo session and watch what real COM objects return.

  1. Open a .ps1 in VS Code; start Creo with a model open.
  2. Ask Claude for a snippet (e.g. the connection code).
  3. Select the lines and press F8 — the PowerShell extension runs the selection against the LIVE Creo session.
  4. Explore any COM object with $model | Get-Member.
  5. Iterate: Write → F8 → Observe → Ask → repeat. Paste any error back for a docs-grounded fix.
Mine trails, don’t guess widgets
Mapkey widget names come from RECORDING real Creo interactions (visible_mapkeys yes in config.pro) and reading working_folder\trail.txt.N. The probe/recorder *-probe.cmd tools capture the exact tokens.

11. The BlueGPT judge / blind-evaluator convergence layer

Confirm results without seeing how they were made
lib\blind_evaluator.ps1 derives a claim, measures ground-truth geometry into a “slice”, and asks an LLM judge to confirm or refute WITHOUT seeing how the claim was produced.

Config resolves first-match-wins:

  1. .bluegpt_judge.json at the repo root (gitignored secret; optional).
  2. ANTHROPIC_BASE_URL + ANTHROPIC_AUTH_TOKEN — already set by Claude Code (they point at litellm.leap.blueorigin.com), so this is the zero-config path in use.
  3. BLUEGPT_API_BASE + BLUEGPT_API_KEY explicit override.

If none resolve it degrades to offline (writes its packet, skips the network) — it never fails a run. Transport is LiteLLM, OpenAI-compatible: POST {base}/v1/chat/completions, Authorization: Bearer <token>, response_format = json_schema (strict). Validate the round-trip:

.\plane-probe.cmd --probe-judge

13. Safety rules

Never mutate a live model without intent
  • Do not auto-run $model.Regenerate($null) (can corrupt a half-committed model), $model.Save() (permanent), or trail commands prefixed < @ ** (view-dependent / unsafe to replay).
  • ID-only, never coordinates: IpfcPoint.Point crashes; foreign / imported bodies are not API-traversable — select by ID and let the human judge geometry.
  • Atomic RunMacro: a dashboard’s command context does NOT survive across RunMacro calls — fire open→set→confirm as one string.
  • Honest verification: “done” means the model actually changed (a VersionStamp canary) or geometry was measured — never “the macro fired”.
  • Close modal Creo dialogs (Parameters / Relations / Find) before an API call or it can hang.

14. Canary gating

A no-op macro aborts — it never lies
Every model-mutating macro is guarded by a VersionStamp / feature-diff canary. A macro that changes nothing (e.g. a mis-named widget) ABORTS and reports; it never silently no-ops or falsely claims success.
